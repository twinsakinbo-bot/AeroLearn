# AeroLearn repository audit

## Security follow-up — 26 November 2026

This section supersedes the historical deployment status below. The 25 November hardening migration is present in the live project; today's database checks were read-only. Screened all 47 API route files, the auth callback, request/auth helpers, outbound fetches, payment/AI paths, PWA headers and live RLS catalogs. This is a targeted review, not an exhaustive penetration test or a promise of no bugs.

| Severity | Verified finding | Implemented correction |
| --- | --- | --- |
| High | `app/api/onboarding/welcome/route.ts` verified a token but accepted an arbitrary recipient from the request body, without a sending limit. A signed-in caller could use it to send unwanted mail. | Recipient/name now come from the server-verified Auth account, require confirmed email, and have a shared once-per-day account limit. |
| High | `lib/safe-fetch.ts` resolved DNS for validation and then resolved again during fetch, leaving a DNS-rebinding SSRF gap. Its timer was cleared after response headers, so a stalled body could hold a request open. | Native HTTP(S) transport pins validated DNS addresses while retaining hostname/TLS validation. One deadline covers DNS, redirects and decoded body consumption. Private/transition addresses are rejected; byte caps apply after decompression. |
| Medium | `app/auth/callback/route.ts` accepted `/\\evil.example` because it only rejected `//`; URL parsing treats backslashes as separators and redirects off-origin. | `safeNextPath` rejects backslashes/control characters and verifies the resolved origin. |
| Medium | Signup, confirmation resend, reset and contact limits in `lib/rate-limit.ts` were process-local and reset between instances. | Public mail endpoints now use the existing service-only atomic database counter, with hashed IP/email identifiers, per-recipient auth-email limits, Retry-After and fail-closed behavior. Welcome mail and link previews also have shared limits. |
| Medium | `app/api/auth/reset-password/route.ts` returned different success messages for existing and missing accounts. | Identical public response for successful dispatch, missing accounts and provider failures; input validation added. Timing-based enumeration and signup's deliberate duplicate-email response remain outside this fix. |
| Medium | `app/api/link-preview/route.ts` explicitly marked authenticated previews public-cacheable. | All preview responses use private/no-store. |
| Low | Rejected requests continued growing the process-local limiter's timestamp list and extended the window. | Only allowed attempts are stored. |
| Low | Invalid session tokens produced 500s in lesson import and gamification login/claim. | Shared authorization gates return authentication errors before business logic; gamification no longer echoes raw internal exceptions. |

Verification: 39 automated tests; 102 HTTP checks against a local production build for absent/invalid tokens; lint, TypeScript and production build; five SQL suites on disposable PostgreSQL (including shared rate-limit enforcement/reset/client denial). All passed. Controlled HTTP tests exercise DNS pinning, private redirects, stalled DNS/body, compressed-body caps and markup/redirect regressions. A live outbound HTTPS smoke attempt from this workspace could not resolve the domain; production outbound-provider compatibility is not claimed from that attempt. No test emails or test users were created in production.

Live catalog: all 19 public tables have RLS; payment/reward/rate-counter RPCs deny direct anonymous/authenticated execution. The `public_profiles` security-definer view intentionally exposes only the listed public identity/progress fields and requires a signed-in caller; changing it to security-invoker without redesign would break community discovery. The advisor still flags this design, caller-scoped authorization helpers, and [disabled leaked-password protection](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection). Private rate/quota/licence tables intentionally have no client policies.

Remaining material risks: client-writable XP/coins/progress, client-visible formative answer keys, race between AI quota precheck and provider work, non-atomic multi-document compatibility transactions, and manual bank-transfer review. The referral/demo APIs still reference absent tables. Lesson import replacement currently deletes the old lesson before writing its replacement and can lose it on a later failure; this requires a stable-ID replacement fix. Dependency audit at review start: 0 critical, 22 high, 5 moderate, 6 low (33 total), including development/PWA chains and the admin-only document parser. These are not declared resolved by this code review. Shared counters also need a retention strategy at high volume. No load, full payment-provider, backup-restore, or low-end Android certification is claimed.

## Historical baseline — before the 25 November rollout

Audit date: 25 November 2026. Branch: `codex/security-production-hardening`. Scope: 321 tracked files at baseline across `app/`, `components/`, `lib/`, `desktop-app/`, `src-tauri/`, `supabase/`, PWA assets, Firebase legacy rules and deployment configuration. Every API route was screened for an authorization gate; migrations and deployment/PWA configuration were read in detail. Findings below combine source inspection, local checks, and read-only catalog checks against the connected AeroLearn Supabase project. No project data or schema was changed.

## RLS policy review

`0001_init.sql` enables RLS on all 14 document tables. `0002_licence_codes.sql` enables RLS and revokes client access to code, batch and duration tables. The `0003` migration tightens the named policies below. Catalog and functional SQL checks pass locally after migration; real account and HTTP tests remain required on Supabase staging.

### Connected project verification

Read-only Supabase tool calls found an active AeroLearn project with existing users, lessons, questions and messages, and **no development branches**. Its catalog still has the broad `users_select`, owner-only `users_insert`, client-writable `challenge_results`, and `ai-bot`-writable `messages_insert` policies from `0001`. The private `receipts` bucket has no bucket-level size or MIME limit, and the owner can delete uploaded evidence. The `public_profiles` view and `0003` functions are absent. The migrations listing is empty because SQL Editor application is not recorded there; the catalog provides the evidence that `0001` and `0002` objects exist and `0003` has not been applied. Nine `plan_durations` rows were read directly; the `list_tables` row estimate of zero was stale.

The Supabase security advisor reported [8 mutable function search paths](https://supabase.com/docs/guides/database/database-linter?lint=0011_function_search_path_mutable), [5 security-definer functions executable by `anon`](https://supabase.com/docs/guides/database/database-linter?lint=0028_anon_security_definer_function_executable), and [disabled leaked-password protection](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection). The repository migration now pins the relevant function paths and revokes anonymous redemption and direct trigger-function execution. `is_admin` and `in_conversation` remain callable because RLS policies need them; their return values are scoped to the caller. Enable leaked-password protection in the project Auth settings. The performance advisor reported [six per-row auth checks](https://supabase.com/docs/guides/database/database-linter?lint=0003_auth_rls_initplan) and [many permissive-policy overlaps](https://supabase.com/docs/guides/database/database-linter?lint=0006_multiple_permissive_policies); `0003` fixes the profile check and removes the challenge result overlap, but the other findings need a staged policy review before further rewrites. No advisor finding was resolved on the connected project during this audit.

## Performance and quality observations

The web build before parser splitting measured 313 kB first-load JavaScript for `/admin/question-importer`; after on-demand SheetJS/DOCX loading it measured 191 kB, a 122 kB (39%) reduction for that route. Shared first-load JavaScript remained 105 kB. Other routes in the earlier build included `/app/learn/[id]` at 296 kB, notes at 291 kB and messages at 225 kB. The current desktop bundle is 233.81 kB JavaScript (72.65 kB gzip) and 35.37 kB CSS (7.18 kB gzip). A comparable pre-change production build was not captured, so no overall before/after claim is made. PDF parsing and jsPDF were already dynamically imported. The unused 3D hat component and its Three.js dependencies were removed after a repository reference search. `users_xp_idx` and other JSON expression indexes exist in `0001`; the projected public view may need a dedicated ranking query/index at scale. Slow-network and low-end Android performance need device and network profiling before numerical claims.

## Verification boundaries

`npm run test:db:local` applies the complete migration chain to an isolated PostgreSQL 17 container, then runs four SQL suites: policy catalog, account-level RLS, atomic payment approval and one-time licence redemption. All pass. It uses minimal Auth/Storage interface stubs and fake account IDs; every functional test rolls back its rows. The script is checked into the repository and runs in CI. This does not simulate Supabase Auth HTTP, real JWT verification, Storage HTTP, concurrent requests, or email delivery.

Local lint, TypeScript, unit tests, web production build, desktop build and npm audits are recorded in the final report. Current web `npm audit` reports 0 critical, 22 high, 5 moderate and 6 low (33 total); `--omit=dev` reports 0 critical, 9 high, 4 moderate and 6 low (19 total). A verified PostCSS override removes Next.js's old nested version; an override updates `serialize-javascript`. Remaining high reports include Workbox dependencies under the PWA plugin, and npm reports no automatic fix for those dependency chains. Desktop reports 0 advisories. The migration was not applied to the connected AeroLearn project. SQL behavior is now tested locally; real Supabase account flows, payment HTTP integration, email delivery, AI output and browser upgrade behavior remain staging gates. The old `firestore.rules` and `storage.rules` are not active controls for Supabase. Tauri installation and platform signing are not covered by a Vite build.

### Lesson formatting follow-up — 26 November 2026

- **Medium / verified:** Lesson and note readers omitted GFM table support and only recognized dollar-delimited maths. LaTeX `\(...\)` / `\[...\]` became literal text after Markdown escaping. Affected: `app/app/learn/[id]/page.tsx` (including worked examples) and `app/app/notes/page.tsx`.
- **Fixed:** Shared `LearningMarkdown` renderer enables GFM and normalizes LaTeX delimiters while preserving code samples and existing dollar maths. Raw HTML remains disabled. Tables and display equations scroll within their containers; rendering is memoized when content is unchanged.
- **Verification:** 30 automated tests passed, including three renderer regressions (equations/tables, existing formatting, and unsafe markup). Lint, TypeScript, and production build passed. Chromium fixture checks at 360px and 1280px in light/dark themes rendered six math expressions and one table without document overflow. These were renderer fixtures, not an authenticated production lesson session.
